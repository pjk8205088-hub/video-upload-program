# 동영상 업로드 프로그램 요구사항

## 1. 프로젝트 개요

동영상 업로드 프로그램은 촬영본·편집본·검수용 프리뷰를 한 곳에 업로드하고, 업로드 상태와 파일 정보를 빠르게 확인할 수 있는 로컬 미디어 작업공간이다. MVP는 단일 로컬 워크스페이스를 대상으로 하며 별도 계정 생성 없이 실행한다.

## 2. 프로젝트 목적

- 파일 탐색기만으로는 확인하기 어려운 업로드 상태를 시각화한다.
- 영상 파일을 끌어놓는 짧은 흐름으로 저장까지 완료한다.
- 업로드된 파일의 이름, 형식, 크기, 등록 시각을 한 눈에 보여준다.
- 서버와 데이터베이스를 확장하기 쉬운 API·데이터 구조로 시작한다.

## 3. 해결하려는 문제

- 업로드가 실제로 끝났는지 사용자가 알기 어렵다.
- 파일이 어디에 저장되었는지, 어떤 형식인지 다시 확인해야 한다.
- 실패한 파일의 원인이 모호하면 사용자가 같은 오류를 반복한다.

## 4. 대상 사용자

영상 편집자, 콘텐츠 운영자, 1인 제작자, 내부 검수 담당자 등 로컬 PC에서 여러 동영상 파일을 반복적으로 다루는 사람.

## 5. 핵심 사용자 시나리오

사용자는 업로드 센터를 열고 파일을 끌어놓는다. 프로그램은 형식·크기를 확인한 뒤 진행률을 보여주고, 완료된 영상은 내 동영상 목록에 추가한다. 사용자는 파일명으로 검색하거나 필요 없는 파일을 삭제한다.

## 6. 기능 요구사항

### FR-01. 동영상 선택

- 파일 선택 버튼과 드래그 앤 드롭을 모두 제공한다.
- MP4, MOV, WebM, MKV 확장자를 지원한다.
- 여러 파일을 한 번에 선택할 수 있다.

### FR-02. 업로드 검증

- 빈 파일은 거부한다.
- 파일 1개당 최대 크기는 2 GB다.
- 지원하지 않는 형식에는 허용 형식과 해결 방법을 안내한다.

### FR-03. 업로드 진행률

- 대기·업로드 중·완료·실패 상태를 구분한다.
- 업로드 중 퍼센트를 표시한다.
- 실패 시 사용자에게 다시 시도할 수 있는 메시지를 표시한다.

### FR-04. 영상 목록

- 파일명, 포맷, 용량, 업로드 시각, 상태를 표시한다.
- 파일명 검색을 지원한다.
- 최신순과 오래된순 정렬을 지원한다.

### FR-05. 영상 삭제

- 삭제 전에 확인을 받는다.
- 실제 저장 파일과 메타데이터를 함께 삭제한다.

## 7. 비기능 요구사항

- 최신 Chrome·Edge·Safari에서 동작한다.
- 모바일 폭 320px 이상에서 핵심 업로드 흐름을 사용할 수 있다.
- 키보드 포커스가 보이고, `prefers-reduced-motion`을 존중한다.
- 업로드 파일명은 저장 경로로 직접 사용하지 않아 경로 조작을 방지한다.
- 서버 재시작 후에도 목록과 파일이 유지된다.

## 8. 권한 및 역할

MVP에서는 로컬 워크스페이스의 단일 관리자만 사용한다. 로그인·다중 사용자 권한은 후속 범위로 남긴다.

## 9. 데이터 요구사항

영상 메타데이터는 `data/videos.json`, 원본 파일은 `uploads/`에 저장한다. 메타데이터에는 원본 파일명, 저장 파일명, MIME 타입, 크기, 상태, 생성 시각, 접근 URL이 포함된다.

## 10. 예외 상황

- 지원하지 않는 확장자 또는 MIME 타입
- 최대 크기 초과
- 네트워크 중단 또는 서버 저장 실패
- 존재하지 않는 영상 삭제 요청
- 손상된 메타데이터 파일

## 11. 보안·운영 고려사항

- 저장 파일명은 서버가 생성한 ID를 사용한다.
- 정적 파일 및 업로드 경로는 허용 디렉터리 밖으로 이탈할 수 없어야 한다.
- 본 MVP는 로컬 전용이므로 인증·바이러스 검사·오브젝트 스토리지는 범위 밖이다.

## 12. 개발 범위

### 이번 단계

업로드 대시보드, 파일 검증, 진행률, 목록, 검색, 정렬, 삭제, 로컬 영속 저장, 반응형 UI, 기본 테스트.

### 다음 단계 후보

썸네일 생성, 영상 재생 상세 화면, 로그인·권한, S3 호환 오브젝트 스토리지, 재개 업로드, 업로드 취소, 서버 측 트랜스코딩.
