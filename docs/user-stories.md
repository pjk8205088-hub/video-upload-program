# 동영상 업로드 프로그램 사용자 스토리

## 일반 사용자

## US-001. 동영상 업로드

As a 영상 제작자,
I want to 파일을 끌어놓아 업로드하고 싶다,
So that 작업 중인 영상을 빠르게 보관할 수 있다.

### 인수 조건

- [x] 파일 선택과 드래그 앤 드롭을 모두 사용할 수 있다.
- [x] 여러 파일을 한 번에 추가할 수 있다.
- [x] 업로드가 완료되면 내 동영상 목록에 나타난다.

## US-002. 업로드 진행 확인

As a 영상 제작자,
I want to 업로드 진행률을 보고 싶다,
So that 파일이 멈췄는지 기다려야 하는지 알 수 있다.

### 인수 조건

- [x] 업로드 큐에 파일명과 진행률이 표시된다.
- [x] 완료와 실패 상태가 구분된다.
- [x] 실패 원인이 사용자에게 표시된다.

## US-003. 파일 검색

As a 콘텐츠 운영자,
I want to 파일명으로 영상을 검색하고 싶다,
So that 목록이 많아져도 원하는 파일을 찾을 수 있다.

### 인수 조건

- [x] 검색어가 파일명에 포함된 결과만 표시된다.
- [x] 검색어를 지우면 전체 목록이 다시 표시된다.

## US-004. 오래된 영상 정리

As a 워크스페이스 관리자,
I want to 불필요한 영상을 삭제하고 싶다,
So that 저장공간을 관리할 수 있다.

### 인수 조건

- [x] 삭제 전 확인 단계가 있다.
- [x] 삭제 후 목록과 저장공간 표시가 갱신된다.
- [x] 실제 업로드 파일도 함께 삭제된다.

## 비회원 사용자

## US-005. 지원 파일 안내

As a 처음 방문한 사용자,
I want to 업로드 가능한 형식과 크기를 미리 알고 싶다,
So that 실패할 파일을 선택하지 않을 수 있다.

### 인수 조건

- [x] 업로드 영역에 지원 확장자와 최대 용량이 표시된다.
- [x] 잘못된 파일 선택 시 구체적인 안내가 표시된다.

## 시스템 관리자

## US-006. 재시작 후 데이터 유지

As a 시스템 관리자,
I want to 서버를 재시작해도 메타데이터가 남아 있기를 원한다,
So that 작업 목록을 잃지 않을 수 있다.

### 인수 조건

- [x] 메타데이터는 JSON 파일에 저장된다.
- [x] 서버 시작 시 JSON 파일이 없으면 빈 목록을 만든다.

## US-007. 안전한 저장 경로

As a 시스템 관리자,
I want to 원본 파일명이 저장 경로를 조작하지 못하게 하고 싶다,
So that 로컬 파일 시스템을 보호할 수 있다.

### 인수 조건

- [x] 저장 파일명은 서버 생성 ID를 사용한다.
- [x] 정적 파일 접근 경로를 public 디렉터리 안으로 제한한다.
